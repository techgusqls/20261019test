# 기술실 기자재 관리 웹앱

Python + Streamlit + Google Sheets로 구동하는 학교 기술실 기자재 관리 앱입니다. 기자재 목록, 대여·부분 반납, 연체 확인, 수리·분실 관리, 변경 이력, CSV 내보내기를 제공합니다.

## 1. 프로젝트 구조

```text
tech-room-inventory/
├── app.py
├── requirements.txt
├── README.md
├── .gitignore
└── .streamlit/
    └── secrets.toml.example
```

## 2. 사전 준비

- Google 계정 및 Google Sheets 문서
- Google Cloud 프로젝트에서 Google Sheets API 활성화
- 서비스 계정 생성 및 JSON 키 발급
- Python 3.10 이상 권장
- GitHub 계정 및 Streamlit Community Cloud 계정

## 3. Google Sheets 준비

1. Google Sheets에서 빈 스프레드시트를 생성합니다.
2. 브라우저 주소창의 문서 URL을 복사합니다.
3. 서비스 계정 생성 단계에서 발급한 JSON 파일의 `client_email` 주소를 확인합니다.
4. 해당 이메일을 스프레드시트의 **편집자**로 공유합니다. 서비스 계정에 문서 접근 권한이 없으면 앱이 동작하지 않습니다.
5. 앱 첫 실행 시 아래 네 탭이 없으면 생성됩니다.
   - `기자재목록`
   - `대여반납기록`
   - `수리기록`
   - `변경이력`
6. 기존 탭에 컬럼이 일부 빠져 있으면 누락 컬럼을 오른쪽에 추가합니다. 기존 데이터 행을 초기화하거나 삭제하지 않습니다.

Google Cloud Console에서 서비스 계정을 만들 때 JSON 키를 다운로드합니다. JSON 키의 내용을 다른 사람에게 공개하거나 GitHub에 커밋하지 마세요. 서비스 계정 JSON 파일 자체를 프로젝트 폴더에 둘 필요는 없습니다. 필요한 값은 로컬 Secrets 파일에 복사합니다.

## 4. Google Sheets URL 설정

`app.py` 상단의 다음 값을 실제 문서 URL로 바꿉니다.

```python
GOOGLE_SHEET_URL = "https://docs.google.com/spreadsheets/d/실제_문서_ID/edit"
```

요청된 운영 방식대로 URL은 코드에 직접 둡니다. URL 자체는 인증 비밀키가 아니지만, 문서 공유 권한은 반드시 필요한 사용자에게만 부여하세요.

## 5. 로컬에서 실행

Windows PowerShell 기준:

```powershell
cd tech-room-inventory
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .streamlit\secrets.toml.example .streamlit\secrets.toml
```

`.streamlit/secrets.toml`을 열고 다음 항목을 실제 값으로 바꿉니다.

- `app_password`: 앱에 접속할 공유 비밀번호. 예시 문자열을 반드시 바꾸세요.
- `[gcp_service_account]`: Google Cloud에서 발급한 서비스 계정 JSON의 각 값.
- `private_key`: JSON의 `private_key` 값을 줄바꿈 `\n`이 포함된 형태로 그대로 붙여 넣습니다. TOML 문자열의 바깥쪽 큰따옴표도 유지합니다.

실행:

```powershell
streamlit run app.py
```

터미널에 표시되는 로컬 URL을 브라우저에서 엽니다. `.streamlit/secrets.toml`은 `.gitignore`에 등록되어 있으므로 Git에 추가하지 마세요. 커밋 전에 `git status`로 다시 확인하는 습관을 권장합니다.

## 6. GitHub에 업로드

GitHub에서 새 저장소를 만듭니다. 실제 비밀키는 업로드하지 않습니다.

```bash
git init
git add app.py requirements.txt README.md .gitignore .streamlit/secrets.toml.example
git status
git commit -m "Create technology room inventory app"
git branch -M main
git remote add origin https://github.com/내계정/내저장소.git
git push -u origin main
```

`git status` 결과에 `.streamlit/secrets.toml`이나 서비스 계정 JSON 파일이 나오면 커밋하지 말고 `.gitignore` 및 스테이징 상태를 바로잡으세요. 이미 비밀키를 GitHub에 올린 적이 있다면 파일만 지우는 것으로 끝내지 말고 Google Cloud에서 해당 키를 폐기하고 새 키를 발급하세요.

## 7. Streamlit Community Cloud 배포

1. Streamlit Community Cloud에 로그인하고 GitHub 계정을 연결합니다.
2. **Create app**에서 저장소, 브랜치(`main`), 메인 파일 경로(`app.py`)를 선택합니다.
3. 고급 설정의 Secrets 영역에 로컬 `.streamlit/secrets.toml`의 내용을 붙여 넣습니다. 예시 값을 그대로 사용하지 마세요.
4. 배포합니다. 앱 시작 실패 시 앱의 관리 화면에서 로그를 확인하고 `GOOGLE_SHEET_URL`, API 활성화, 서비스 계정의 편집 권한, Secrets 문법을 점검합니다.
5. 코드를 수정하고 GitHub에 push하면 연결된 앱이 다시 배포됩니다.

Streamlit 공식 문서도 비밀값을 저장소에 커밋하지 말고, 로컬에서는 `.streamlit/secrets.toml`, Community Cloud에서는 앱의 Secrets 설정을 쓰도록 안내합니다: https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management

## 8. 기능 안내

### 대시보드

- 활성 기자재의 보유 수량, 사용 가능 수량, 대여 중 수량, 수리 중 수량, 분실 수량
- 분류별 보유 현황, 최근 등록 기자재, 최근 대여·반납 이벤트, 연체 내역

### 기자재 목록 및 등록

- 기자재명·관리번호 검색, 분류·위치·상태 필터, 정렬 및 상세 정보 수정
- 관리번호 자동 생성(`TR-YYYYMMDD-001` 형식)과 중복 검증
- 삭제 대신 비활성화하여 관련 이력 보존
- 보유 수량을 줄일 때 대여·수리·분실 수량 합계보다 작게 줄이지 못하도록 검증

### 대여·반납

- 대여할 때 현재 Sheets 데이터를 다시 읽고 대여 가능 수량을 재검증
- 각 대여는 고유한 거래 ID로 저장합니다.
- 부분 반납마다 새로운 반납 이벤트 행을 추가하고 `원거래 ID`로 원래 대여 건에 연결합니다.
- 미반납 수량은 대여 수량에서 해당 거래의 모든 반납 이벤트 합계를 차감해 계산합니다.
- 반납 예정일이 오늘보다 이전이고 미반납 수량이 남아 있으면 연체로 표시합니다.

### 수리·분실·폐기

- 수리 접수 수량은 대여 가능 재고에서 차감되며 완료 처리 시 다시 대여 가능 수량에 포함됩니다.
- 분실 처리와 분실 복구는 `분실 수량`과 변경 이력에 반영됩니다.
- 폐기 상태인 기자재는 대여 가능 수량이 0으로 처리됩니다.
- 분실·폐기 변경은 변경 이력에서 확인할 수 있습니다.

### 변경 이력 및 내보내기

- 등록·수정·비활성화·대여·반납·수리·분실 변경 작업을 변경이력 탭에 기록합니다.
- 기자재 목록, 대여·반납, 수리 기록, 변경 이력을 UTF-8-SIG CSV로 다운로드합니다.
- 현재 목록 내보내기에는 화면에서 선택한 필터가 적용됩니다.

## 9. 데이터 보호 및 동시 사용 주의

- 앱은 단순한 공유 비밀번호를 사용합니다. 이것은 사용자별 계정·역할 관리가 아니며, 누가 어떤 권한으로 로그인했는지 증명하지 않습니다. 학교 내부의 승인된 사용자에게만 비밀번호를 공유하세요. 민감한 학생 정보가 포함되는 경우 학교의 개인정보 보호 지침과 승인된 배포 범위를 따르세요.
- 서비스 계정은 필요한 스프레드시트에만 편집 권한을 부여하고, 키가 노출되면 즉시 폐기·재발급하세요.
- 앱 내부에서 잠금을 사용하고 대여·반납·수리 처리를 직전에 최신 시트 데이터로 다시 검증합니다. 관련 행 변경은 Google Sheets API의 한 번의 `batchUpdate` 요청에 묶어 저장하므로 해당 요청 내부의 행 변경은 원자적으로 적용됩니다.
- 그러나 **읽기 → 재고 검증 → 쓰기 전체가 다중 사용자·다중 서버 인스턴스 사이에서 직렬화되는 것은 아닙니다.** 같은 프로세스 안의 앱 요청은 잠금으로 직렬화하지만, 서로 다른 서버 인스턴스나 사용자가 거의 동시에 처리하면 경합 조건이 남을 수 있습니다. Google Sheets는 관계형 DB의 행 잠금·트랜잭션·고유 제약을 제공하지 않으므로, 재고가 중요하고 동시 작업량이 많다면 PostgreSQL 같은 트랜잭션 데이터베이스로 이전하는 것이 안전합니다.
- 대여와 반납 이벤트는 별도 행에 누적됩니다. 관리자도 `대여반납기록`의 거래 행을 임의로 지우거나 ID를 수정하지 마세요. 실수로 기록을 바꾸면 재고 계산이 달라질 수 있습니다.
- 이 앱은 매 실행 시 데이터를 다시 읽고 연결 객체만 캐시합니다. 여러 사용자가 동시에 작업하는 경우 새로고침 후 최신 상태를 확인하세요.

## 10. 테스트 시나리오

테스트는 실제 운영 데이터가 아닌 별도의 테스트용 Google Sheets 문서에서 수행하세요.

1. **초기화**: 빈 스프레드시트 URL과 서비스 계정 인증을 설정합니다. 앱 실행 후 네 개 탭과 첫 행의 컬럼명이 생성되는지 확인합니다.
2. **등록**: `충전 드릴`, 분류 `공구`, 보유 수량 `5`, 보관 위치 `공구장 A`로 등록합니다. 관리번호가 생성되고 기자재목록과 변경이력에 한 행씩 생기는지 확인합니다.
3. **중복 등록 방지**: 자동 생성을 끄고 방금 사용한 관리번호로 다시 등록합니다. 저장이 거부되어야 합니다.
4. **검색 및 필터**: 기자재명 `드릴` 또는 관리번호 일부로 검색하고 분류·보관 위치·상태 필터를 함께 적용합니다.
5. **수정**: 보관 위치와 비고를 바꾸고 저장합니다. 기자재목록 반영 및 변경이력 기록을 확인합니다.
6. **대여**: 5개 중 3개를 대여자 `테스트학생`, 소속 `2학년 1반`, 반납 예정일을 오늘 이후로 설정해 대여합니다. 대여 가능 2개, 대여 중 3개가 되는지 확인합니다.
7. **초과 대여 방지**: 남은 수량보다 큰 대여를 시도합니다. 처리되지 않아야 합니다.
8. **부분 반납**: 해당 거래에서 1개를 반납합니다. `대여반납기록`에 `거래 유형=반납`인 새 행이 생기고 미반납 2개, 대여 가능 3개가 되는지 확인합니다.
9. **전체 반납**: 같은 거래의 나머지 2개를 반납합니다. 미반납이 0이 되고 대여 가능 5개로 돌아오는지 확인합니다.
10. **연체**: 별도 대여를 만들고 반납 예정일을 어제로 설정합니다. 미반납 수량이 남은 동안 대시보드와 대여 현황에 연체가 표시되는지 확인합니다.
11. **수리 접수 및 완료**: 대여 가능 재고 중 1개를 수리 접수합니다. 대여 가능 수량이 1 줄고 수리 중 수량이 1 늘어나는지, 완료 처리 후 다시 복구되는지 확인합니다.
12. **분실 및 복구**: 수량 1개를 분실 처리하고 대여 가능 수량이 1 줄어드는지 확인한 후 분실 복구합니다.
13. **폐기 및 비활성화**: 테스트 기자재 상태를 폐기로 변경해 대여 가능 수량이 0인지 확인합니다. 다른 기자재는 비활성화 후 일반 목록에서 숨겨지고 이력은 남는지 확인합니다.
14. **CSV 내보내기**: 기자재 목록에 분류 필터를 지정한 뒤 CSV를 내려받습니다. Excel에서 한글이 정상적으로 표시되는지 확인합니다. 대여·반납 CSV에 대여 이벤트와 반납 이벤트가 각각 별도 행으로 포함되는지도 확인합니다.
15. **인증·오류 처리**: 틀린 앱 비밀번호, 잘못된 URL, 서비스 계정 미공유 상태를 테스트하고 사용자에게 이해 가능한 메시지가 표시되는지 확인합니다.

## 11. 알려진 범위 및 점검 사항

- 본 앱은 코드 수준의 기본 검증과 데이터 무결성 보호를 제공합니다. 실제 Google 계정, 시트 권한, 서비스 계정 키, 배포 환경을 제공받지 않은 상태에서는 운영 계정에 연결한 엔드투엔드 테스트를 수행할 수 없습니다.
- 기자재목록의 `대여 중 수량`과 `수리 중 수량`은 빠른 확인을 위한 보조 필드입니다. 화면의 핵심 계산값은 대여 이벤트와 미완료 수리기록에서 계산합니다. Sheets를 수동 편집한 후에는 원본 로그와 재고가 일치하는지 점검하세요.
- `실제 반납일`과 `반납 상태`는 각 반납 이벤트 행에 기록됩니다. 부분 반납 이력은 모든 이벤트 행을 통해 확인할 수 있습니다.
